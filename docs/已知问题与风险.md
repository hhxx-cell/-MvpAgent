# 已知问题与风险

以下为当前 MVP 的实际边界。风险状态以已实现代码、本地测试、2026-09-29 Linux Compose 启动及 2026-10-08 服务器回归为准，生产上线前须重新评估。

| 风险 | 影响 | 当前处理与后续动作 |
| --- | --- | --- |
| 仅使用合成订单、文档和对话 | 指标不能代表真实售后流量 | 固定 seed 与 manifest 保证演示可复现；接入真实数据后重建评测集 |
| 固定演示 Bearer Token | 不适合公网或真实账户 | 当前仅限本地/内网演示；`APP_ENV=production` 因缺少真实认证适配器直接拒绝启动，须先实现正式认证与凭证轮换 |
| 规则路由与确定性字符 n-gram 检索 | 对开放表达和复杂语义的泛化有限 | 用 held-out Golden 评测召回与路由；必要时引入模型分类和正式 Embedding |
| 默认规则网关覆盖有限 | 未支持的开放表达或统计会澄清或拒绝 | 当前优先保障安全；兼容模型端点可做结构化路由与 SQL 候选，启用后重新评测路由、SQL 与攻击拦截 |
| SQLite 运行时状态库 | 多副本并发、备份和恢复能力有限 | MVP 单实例使用独立文件；扩大部署前设计共享状态库和迁移方案 |
| API 启动时重建 Qdrant 集合 | 启动耗时与多副本竞争风险 | 当前约 30 篇文档且单实例；扩容前改为版本化增量索引和原子切换 |
| 外部模型端点可变 | 输出、延迟和安全表现随模型而变 | 默认规则网关 49/49 Golden 通过。已在 Linux 服务器手动配置 `.env`，模型接口与 Compose API readiness 连通；[真实兼容 API 的本地试验和服务器复测](evidence/model-api/README.md)均为 6 条通过 4 条。服务器最终复测中，消费统计被误判为工单，订单查询在 20 秒超时；关键安全失败 0，但 `release_gate=failed`。先修正路由与超时，再重跑完整安全和准确性评测 |
| Linux Compose 冒烟规模有限 | 单次启动和合成请求不能证明长期稳定性或容量 | 已在 Docker Engine 29.4.3 / Compose v5.1.3 完成 `up --build -d`，API/mock 健康、Qdrant `/healthz`、API readiness 和端到端冒烟均通过；见[服务器证据](evidence/compose-server/summary.json)。服务器总内存约 1.7 GiB，三个容器单次采样合计约 251 MiB，仍需压测后确定资源预算 |
| 业务延迟、并发与 QPS 未定 | 不能承诺生产 SLO 或报价 | 在目标硬件压测后确定容量、超时和资源预算 |
| Redis 缓存、图表和长会话压缩 | 加分能力尚未全部交付 | Linux x86_64 规则网关离线包已生成并完成镜像载入式安装；其余能力按实施文档第二阶段实施 |
| 离线包尚未经过物理断网与干净主机验证 | 同一台联网服务器上已完成 SHA256 校验、镜像载入、独立无构建/无拉取 Compose 安装及 11 项冒烟；这不能证明完全隔离网络或另一台空白主机的操作结果 | 在隔离网络的 Linux x86_64 目标机重做安装和[复验](../scripts/verify_compose.sh)；当前[安装记录](evidence/offline-compose/offline-install.log)和[冒烟汇总](evidence/offline-compose/summary.json)可供核对。详见[离线部署手册](离线部署.md) |
| 已确认的评测门槛基于合成 Golden | `release_gate=passed` 不能代表真实客户分布或真实模型效果 | [进程内完整报告](../eval/报告.md)为 49/49、发布门槛通过、安全违规 0。更换数据或模型后重跑完整门槛和安全门禁 |
| 演示录屏尚未制作 | 实施文档第 20、21 节的正式交付检查暂不能勾选录屏项 | 保留为低优先级交付项；录制时覆盖政策问答、数据查询、缺参澄清、工具链、故障降级和 Trace，并只使用合成数据 |

## 发布前必须完成

1. 复核[Linux Compose 运行证据](evidence/compose-server/summary.json)与[外部 HTTP Golden 报告](evidence/compose-server/eval-report.md)；HTTP 46/49、0 失败、0 安全失败，3 条故障注入跳过导致 `release_gate=incomplete`，由进程内 49/49、`release_gate=passed` 覆盖。
2. 上线前按目标负载压测，不将单次内存采样或冒烟结果作为 SLO。
3. 核对 Golden 报告、自动化测试和 SQLite 只读/越权证明，以及日志、Trace、SSE、指标和截图的脱敏。
4. 若处理真实数据，先替换演示认证和存储策略，再进行独立安全审查。
