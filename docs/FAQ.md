# 常见问题

## 为什么订单原始文件有 200 条，而数据库只有 190 条？

10 条源记录故意包含缺失字段、未知状态或重复订单号，用于数据质量与防御测试。生成器把它们写入 `database/seeds/rejected_orders.jsonl` 和质量报告；只有通过校验的 190 条进入 SQLite。

## 演示订单和身份是什么？

`demo-user-a` 对应 `user_a`，拥有 `O00001`；`demo-user-b` 对应 `user_b`，拥有 `O00002`。跨用户查询统一返回“未找到或无权访问”。`demo-admin` 仅能读取受保护的 Trace，不拥有业务订单。

## 查询“退货政策”为什么引用某一版文档？

知识库为同一 `policy_key` 保留三版文件，按生效日期和版本裁决。当前退货政策来自 `return_policy_v3.md`，答案应附文档名、`[p-...]` 段落号和生效日期；旧版存在时会说明采用了最新有效版。

## 查询订单和查询消费金额为什么走不同的数据源？

订单和物流当前状态来自 mock API；历史统计来自 SQLite 快照。这样可以清楚区分查询时看到的状态与数据库的历史时间。金额以整数分存储，回答时换算为元。

## “上个月”按哪一天计算？

开发/测试环境按 `data_manifest.json.generated_at` 的固定时间计算，默认是 `2026-09-23T12:00:00+08:00`，所以“上个月”指 2026 年 8 月。需要跨月重放时可设置带时区的 `DATA_REFERENCE_TIME`。Mock 的 `observed_at` 始终是实际接口观测时间，和统计基准不同。

## 为什么不能直接让 Agent 执行任意 SQL？

候选 SQL 必须通过 AST 白名单、对象级授权与参数绑定，再由只读 SQLite 连接执行。写语句、系统表、`SELECT *` 和越权路径会被拒绝。模型只生成候选，不掌握连接和授权上下文。

## 为什么说“需要确认创建工单”，却没有立即建单？

工单是有副作用的操作。Agent 先返回 `action.preview` 并保存参数快照，用户下一轮用 `action_id` 确认后才执行。重复确认使用幂等键，避免创建重复工单。

## 看到“待提交”是否意味着已创建工单？

不是。它表示用户已确认，但上游工单服务暂时不可用，请求已进入独立 Outbox。只有 mock 服务成功返回真实 `ticket_id` 时，才表示建单完成；Outbox 本身写入失败时会报告失败。

## 如何测试 429、超时和 500？

在开发或测试环境设置 `MOCK_SCENARIO_CONTROL_ENABLED=true`，内部调用可带 `X-Mock-Scenario: rate_limit`、`timeout` 或 `server_error`。生产环境拒绝场景头；最终用户消息不能选择故障场景。具体接口见 [mock 服务说明](../mock/README.md)。

## API 一直显示未就绪怎么办？

读取 `/health?readiness=true` 的 `components`。数据库异常先运行 `scripts/verify_data_manifest.py`；向量库异常看 Qdrant 容器与 API 入库日志；mock 异常看其健康检查和内部服务地址。Compose 首次启动时 API 可能等待 Qdrant，配置了失败重启。

## 是否需要公网模型？

默认 `LLM_PROVIDER=rules`，不需要公网模型。`openai_compatible` 可配置公网或本地兼容端点，用于结构化意图路由和 SQL 候选生成；切换后应重跑路由、SQL、安全与答案评测。

## 可以接入真实客服对话或订单吗？

当前版本仅为合成数据 MVP。`APP_ENV=production` 会因缺少真实认证适配器而直接拒绝启动，单纯更换密钥无效。真实数据需要接入正式认证、建立数据授权与留存策略、密钥服务、生产日志脱敏、容量和安全评测；不能直接把真实数据复制进生成器的输出目录。
